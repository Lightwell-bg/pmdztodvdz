# Формат ответов анкеты и тексты вопросов

Это канонический формат, на который опираются:
- `Questionnaire\Validator` — нормализация и серверная проверка;
- `Rules\Evaluator`;
- фронтенд (`assets/questionnaire.js`).

Значения перечислений берутся из `Questionnaire\Labels`.

## Типы

- `date` — строка `YYYY-MM-DD` или `''`. Валидатор проверяет реальность даты (`DateMath::parse`) и диапазон 1950-01-01 … сегодня+3 года. Невалидная дата — ошибка поля.
- `ynu` — `yes` | `no` | `unknown`.
- `text` — строка, обрезается по краям, до 200 символов. Управляющие символы удаляются, HTML не допускается: выводится только экранированной.
- `int` — целое или `null`.
- Строка с `precision`: `exact`, `approx` или `unknown`. При `unknown` даты строки игнорируются и нормализуются в `''`. При `approx` обязательно хотя бы примерное значение даты: месяц выбирается, день ставится `01`.

## Структура (после нормализации)

```text
applicant:
  citizenship: text                  # обязательно
  other_citizenships: text
  eu_status: none|eu_citizen|bg_citizen|unknown
  age: int|null                      # 0..120; null = не указан
  family: self|family
pmzh:
  date_precision: exact|approx|unknown
  decision_date: date                # обязательно при exact/approx
  basis: text                        # своими словами
  basis_article: text                # «чл. 25, ал. 1, т. 6» — если известно
  decision_doc: ynu                  # сохранилось ли решение
statuses: list (0..20) of            # статусы ДО ПМЖ (ПМЖ не дублировать)
  kind: vnzh|study_24v|blue_card|temp_protection|intl_protection|other
  basis: text
  precision: exact|approx|unknown
  from: date                         # дата решения / начала
  end: ended|ongoing|unknown
  to: date                           # обязательна при end=ended и precision≠unknown
statuses_complete: ynu               # «перечислены все статусы с первого приезда»
history:
  gap_without_permit: ynu
  gaps: list (0..10) of { from: date, to: date }   # только при gap_without_permit=yes
  late_renewal: ynu
  refusal: ynu
  pending_decision: ynu
  old_documents: all|partial|none|unknown
trips_any: ynu                       # были ли отсутствия, хотя бы частично попадающие в пятилетний период
trips: list (0..150) of              # только при trips_any=yes
  out: date
  back: date
  countries: text
  precision: exact|approx|unknown
trips_complete: complete|partial|unknown   # только при trips_any=yes
special:
  study_24v: ynu
  studied_other_basis: ynu
  blue_card: ynu
  protection: none|international|temporary|unknown
  temporary_basis: ynu               # au pair, сезонная работа, командирование
  other_eu_status: none|residence|ltr|unknown
housing:
  region: text                       # город/область
  registered_same: ynu               # адресная регистрация там же
  tenure: own|rent|family|other|unknown
  proofs: list of notarial_act|lease|owner_declaration|address_registration|none|unknown
health:
  nzok: ynu
  contributions: ok|gaps|unknown     # только при nzok=yes
  other_cover: none|policy|other|unknown   # только при nzok≠yes
  cover_until: date                  # только при other_cover in (policy, other)
funds:
  income_sources: list of salary|pension|business|rental|other|none|unknown
  income_amount: float|null          # ≥0, ≤ 1 000 000; средний месячный доход
  income_currency: EUR|BGN|other|''
  income_proofs: list of employment_contract|payslips|pension_decision|tax_return|bank_statements|other|none
  savings: ynu
  bank_country: bg|eu|other|''
  dependents: int|null               # 0..20
documents:
  passport_until: date
  pmzh_card_until: date
  adverse: ynu                       # отказы, лишение статуса, иные неблагоприятные решения
  entry_ban: ynu
  extra_check: ynu                   # иные обстоятельства для отдельной правовой проверки
filing:
  planned_date: date                 # '' = расчёт на текущую дату (показывается явно)
```

### Перекрёстные проверки валидатора

Их результат — ошибки, которые человек исправляет:
- `to < from` в статусе;
- `back < out` в поездке;
- `back` позже сегодняшней даты: «укажите только совершённые поездки»;
- `out` позже сегодняшней даты;
- пересечение двух поездок;
- дата подачи в прошлом;
- в периоде без разрешения `to < from`.

### Только предупреждения

Не блокируют отправку и показываются на сводке:
- поездки за пределами пятилетнего периода;
- пустой список поездок при `trips_any=yes`.

## Шаги и тексты вопросов

На каждом шаге есть короткое пояснение, зачем нужны вопросы.

**Шаг 1. О вас.** «Анкета заполняется на одного человека. Если вопрос касается семьи, каждого члена семьи нужно оценивать отдельно».
- Гражданство (`citizenship`): «Ваше гражданство».
- Другие гражданства (`other_citizenships`): «Другие гражданства, если есть».
- `eu_status`: «Есть ли у вас гражданство Болгарии или другой страны ЕС/ЕЭП/Швейцарии?»
- `age`: «Сколько вам полных лет?», чекбокс «Не хочу указывать».
- `family`: «Вы оформляете только себя или есть вопросы и по членам семьи?»

**Шаг 2. ПМЖ и прежние статусы.**
- `pmzh.date_precision` и `pmzh.decision_date`: «Когда принято решение о предоставлении ПМЖ?» Варианты: точная дата / примерно, месяц и год / нет точных данных.
- `pmzh.basis`: «На каком основании получено ПМЖ (своими словами)?»
- `pmzh.basis_article`: «Статья и пункт из решения, если известны».
- `pmzh.decision_doc`: «Сохранилось ли решение о ПМЖ?»
- `statuses` — повторяемый блок «Статусы до ПМЖ», кнопка «Добавить статус»: вид, основание, точность дат, дата начала (решения), состояние (закончился / действует / не знаю), дата окончания.
  Подсказка: «Указывайте даты решений, а не сроки карт. Окончание срока карты само по себе не означает окончания статуса».
- `statuses_complete`: «Это все разрешения на пребывание с момента первого приезда в Болгарию?»
- `history.gap_without_permit`: «Были ли периоды, когда у вас не было действующего разрешения?» При «Да» — повторяемые «Период без разрешения: с … по …».
- `history.late_renewal`, `history.refusal`, `history.pending_decision`: «Были ли просроченные продления?», «Были ли отказы миграции?», «Были ли периоды ожидания решения по продлению или смене статуса?»
- `history.old_documents`: «Сохранились ли старые карты и решения?»

**Шаг 3. Поездки.** Подсказка: «Учитываются все выезды из Болгарии, включая поездки в другие страны ЕС и Шенгена. Укажите поездки начиная с {дата начала пятилетнего периода}». JS считает её от даты подачи или сегодняшней даты: календарные 5 лет назад.
- `trips_any`: «Были ли у вас отсутствия в Болгарии, которые хотя бы частично приходятся на период с {дата}? Учитывайте и поездки, начавшиеся раньше этой даты, если вы вернулись после неё.» Подсказка в шаге при «Да»: «Если поездка началась до {дата}, а закончилась после — укажите её полностью, с настоящей датой выезда.»
- `trips`: повторяемая таблица «Дата выезда из Болгарии / Дата возвращения / Страна(ы) / Точность», кнопки «Добавить поездку» и «Удалить».
  Клиентская подсветка: обратный порядок дат, пересечения, будущие даты. Сервер проверяет то же.
- `trips_complete`: «Это полная история поездок за этот период?»

**Шаг 4. Особые основания.**
- `special.study_24v`: «Было ли у вас разрешение на пребывание для обучения (студент, ученик, стажёр — ст. 24в ЗЧРБ)?»
- `special.studied_other_basis`: «Учились ли вы, проживая на другом основании (например, семейном)?»
- `special.blue_card`: «Была ли у вас Синяя карта ЕС (в Болгарии или другой стране ЕС)?»
- `special.protection`: «Была ли у вас международная или временная защита?»
- `special.temporary_basis`: «Проживали ли вы в Болгарии исключительно на временном основании: au pair, сезонная работа, командирование, трансграничные услуги?»
- `special.other_eu_status`: «Есть ли у вас разрешение на проживание или статус долгосрочно пребывающего в другой стране ЕС?»

**Шаг 5. Жильё и медицинское страхование.**
- `housing.region`: «Город или область, где вы живёте».
- `housing.registered_same`: «Там же ваша адресная регистрация?»
- `housing.tenure`: «Жильё собственное или арендованное?»
- `housing.proofs` (чекбоксы): «Какие документы на жильё у вас есть?»
- `health.nzok`: «Вы застрахованы в болгарской системе здравного осигуряване (НЗОК)?»
- `health.contributions` (если `nzok=yes`): «Взносы платятся без перерывов?»
- `health.other_cover` (если `nzok≠yes`): «Есть ли другое медицинское покрытие?»
- `health.cover_until`: «До какой даты оно действует?»

**Шаг 6. Средства.**
- `funds.income_sources` (чекбоксы): «Источники регулярного дохода».
- `funds.income_amount` и `funds.income_currency`: «Примерный средний доход в месяц». Подсказка: «можно оставить пустым».
- `funds.income_proofs` (чекбоксы): «Чем вы можете подтвердить доход?»
- `funds.savings`: «Есть ли сбережения на счетах?»
- `funds.bank_country`: «В какой стране банк?»
- `funds.dependents`: «Сколько человек на вашем содержании?»

**Шаг 7. Документы, обстоятельства и дата подачи.**
- `documents.passport_until`: «До какой даты действует паспорт?»
- `documents.pmzh_card_until`: «До какой даты действует карта ПМЖ?» Подсказка: «окончание срока карты не равно окончанию права постоянного пребывания».
- `documents.adverse`: «Были ли решения миграции против вас: отказы, лишение статуса и т. п.?»
- `documents.entry_ban`: «Был ли запрет на въезд в Болгарию или ЕС?»
- `documents.extra_check`: «Есть ли другие обстоятельства, которые, по-вашему, требуют отдельной правовой проверки?» Подсказка: «подробности не нужны — анкета их не собирает».
- `filing.planned_date`: «Предполагаемая дата подачи». Подсказка: «если не знаете, оставьте пустым — расчёт будет на сегодня, {сегодняшняя дата}».

**Сводка.**
- Все ответы сгруппированы по шагам, у каждой группы кнопка «Изменить».
- Ниже — предупреждения и текст о назначении сбора данных со ссылкой на политику сайта (`privacy_url` из настроек; без неё — только текст).
- Кнопка «Получить предварительный результат».

Текст о данных: «Ответы нужны только для расчёта предварительного результата и инструкции. Они хранятся на сайте ограниченное время и не передаются в системы аналитики. Номера документов и сканы не запрашиваются».
