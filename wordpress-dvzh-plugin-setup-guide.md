# Настройка опросника ПМЖ → ДВЖ в WordPress

Основано на предоставленном README_RU.md версии 0.1.1 и официальной документации WordPress/EDD. Исходники и установочный ZIP не предоставлены: описанное поведение плагина взято из README, а не подтверждено проверкой его кода.

## Что сейчас нужно сделать

Сообщение «Не выбран товар EDD» означает, что плагин уже активен, но не привязан к товару для оплаты. Начинайте с раздела 2. Раздел 1 нужен только для установки или обновления.

Персональную инструкцию не нужно загружать в товар EDD. Плагин формирует её из анкеты, правил и шаблонов. После подтверждения оплаты он открывает результат и создаёт скачиваемый PDF.

| Что | Где разместить |
|---|---|
| ZIP плагина | Плагины → Добавить новый → Загрузить плагин |
| Статья | Редактор существующей страницы WordPress |
| Шорткод анкеты | Блок «Шорткод» на этой странице |
| Цена услуги | Товар в разделе «Загрузки» EDD |
| Привязка товара и страницы | ПМЖ → ДВЖ → Настройки |
| Редактируемые тексты результатов | ПМЖ → ДВЖ → Шаблоны |
| Персональная инструкция и PDF | Создаются плагином; в товар файлы не прикрепляются |

## 1. Установка или обновление плагина

Если плагин уже активен и открыт экран настроек, этот этап пропустите.

### Если установочный ZIP уже есть

1. Откройте админку WordPress сайта bginfo.eu.
2. Перейдите в «Плагины → Добавить новый».
3. Нажмите «Загрузить плагин».
4. Выберите готовый установочный ZIP из папки `dist` проекта.
5. Нажмите «Установить» и затем «Активировать».
6. При обновлении WordPress предложит заменить установленную версию: используйте замену, без предварительного удаления плагина.

По README настройки и данные сохраняются при замене. Перед обновлением сделайте резервную копию сайта и базы. Опцию удаления данных при деинсталляции оставляйте выключенной.

### Если есть только исходники

Откройте терминал в корневой папке проекта, где находится `bin/build-zip.php`, и выполните:

```powershell
php bin/build-zip.php
```

В `dist` появится архив вида `_<N>bginfo-pmzh-dvzh.zip`. `<N>` обозначает номер сборки; выбирайте фактически созданный архив. Скрипт по README автоматически увеличивает версию.

Если команда PHP не найдена, используйте полный путь к установленному `php.exe` или попросите исполнителя передать собранный ZIP. На хостинге не нужно запускать Composer: PDF-зависимости должны уже входить в сборку.

## 2. Создание товара EDD — ваш текущий этап

1. Откройте «Загрузки → Добавить» / «Downloads → Add Download».
2. Название товара: **Персональная инструкция по переходу с ПМЖ на ДВЖ в Болгарии**.
3. Описание можно пока оставить пустым. Товар нужен для оплаты; статья и опросник находятся на отдельной странице.
4. Если доступен тип товара «Service / Услуга», он подходит для услуги без прикреплённых файлов. Если такого типа в вашей версии нет, используйте обычный одиночный товар без файлов.
5. Введите выбранную вами цену услуги. Валюта используется из настроек EDD. Вариативные цены для первого запуска не включайте.
6. Блок файлов оставьте пустым. Статический PDF или MD прикреплять не нужно.
7. Для рабочего запуска нажмите «Опубликовать». Товар не делайте приватным или защищённым паролем. Черновик используйте только на этапе подготовки.

В README разрешён черновик, но стандартная документация EDD рекомендует публикацию для продажи. Продажа неопубликованного товара этим плагином отдельно не проверена. Исключение из витрины — отдельная настройка, если она есть в вашей теме/расширениях; это не то же самое, что приватная публикация.

Прямую кнопку покупки этого товара в статье не размещайте: штатная кнопка появляется после заполнения опросника и создаёт привязку покупки к анкете.

## 3. Привязка товара к плагину

1. Откройте «ПМЖ → ДВЖ → Настройки».
2. Найдите выбор товара EDD.
3. Выберите созданный товар «Персональная инструкция по переходу с ПМЖ на ДВЖ в Болгарии».
4. Нажмите «Сохранить».
5. Если используется одна обычная цена, выбор варианта не требуется. Если товар имеет варианты, выберите нужный вариант и сохраните повторно.

Предупреждение о невыбранном товаре должно исчезнуть. Если «Готовность продажи» показывает другую причину, устраните именно её. Сообщение «Всё готово» подтверждает заполнение проверяемых настроек, но не заменяет тест оплаты.

## 4. Настройка страницы и остальных полей

На том же экране:

| Поле | Что указать |
|---|---|
| Страница с анкетой | Существующую страницу со статьёй и будущим шорткодом |
| Политика конфиденциальности | Полный адрес реальной действующей политики вашего сайта |
| Срок хранения черновиков | Для первого запуска можно оставить 30 дней из README |
| Срок хранения неоплаченных анкет | Можно оставить 90 дней |
| Срок действия ссылки из письма | Можно оставить 30 дней |
| Удаление данных при деинсталляции | Выключено |
| Такса и дата проверки | Только проверенное описание актуальных государственных сборов; не цена вашей услуги |
| Ориентир дохода | Подтверждённая сумма, валюта, дата проверки и пояснение применимости |

Сохраните настройки.

### Особенность ориентира дохода

По README без заполненного ориентира дохода проверка средств всегда приводит к «нужна проверка». Это предусмотренное ограничение оценки.

Не вписывайте произвольную сумму ради положительного результата. Перед заполнением нужно установить, что именно сравнивает код: доход за месяц/год, доход заявителя/семьи и применимость к пенсионерам. В приложенном README этих деталей недостаточно. До уточнения оставьте поле незаполненным: результат должен честно сообщать о необходимости проверки средств.

## 5. Встраивание в страницу WordPress

Откройте существующую страницу в редакторе. Якорь и порядок блоков должны быть именно такими.

### После первого абзаца статьи

Добавьте блок «Произвольный HTML»:

```html
<p><strong>Хотите узнать, можете ли вы перейти с ПМЖ на ДВЖ?</strong> <a href="#anketa-dvzh">Заполните опросник по вашей ситуации</a>.</p>
```

### Перед разделом «Законы, официальная процедура и формы»

Добавьте заголовок в блоке «Произвольный HTML»:

```html
<h2 id="anketa-dvzh">Проверка возможности перехода на ДВЖ</h2>
```

Сразу под ним добавьте отдельный блок WordPress «Шорткод». Вставьте в него ровно:

```text
[bginfo_pmzh_dvzh_questionnaire]
```

После этого блока должен идти существующий раздел «Законы, официальная процедура и формы».

Если страница сейчас состоит из одного большого блока HTML, разделите его в месте вставки:

1. Первый блок HTML — статья до опросника, включая заголовок с якорем.
2. Блок «Шорткод» — только шорткод плагина.
3. Второй блок HTML — законы, источники и дата проверки.

Удалите прежний HTML-комментарий-плейсхолдер. Не оформляйте шорткод блоком «Код»: нужен именно блок «Шорткод».

В классическом редакторе поместите шорткод отдельной строкой между заголовком опросника и разделом источников.

Сохраните/обновите страницу и убедитесь, что она выбрана в настройках плагина. Якорь `anketa-dvzh` должен встречаться один раз.

## 6. Где изменять тексты инструкций

По README инструкция уже собирается из ответов и встроенной логики. Отдельного импорта полного MD/DOCX/PDF через админку не описано.

Откройте «ПМЖ → ДВЖ → Шаблоны». Там изменяются тексты статусов, предложения покупки, оговорки и пояснения по кодам замечаний. Поля принимают простой текст.

Не вставляйте всю публичную статью в одно поле: персональная инструкция должна зависеть от ответов.

Если нужно изменить сам состав документа, алгоритм или добавить новые условные разделы, это изменение кода плагина исполнителем и выпуск нового ZIP. По README правила доступны в админке только для чтения; изменение их метаданных не обновляет расчёт.

Перед продажей проверьте несколько разных оплаченных тестовых инструкций: полный документ должен различаться по ситуациям и содержать конкретные шаги и документы. README описывает структуру, но сам по себе не подтверждает качество фактического текста.

## 7. Проверка без оплаты

Откройте страницу в режиме инкогнито:

1. Нажмите ссылку после первого абзаца. Она должна прокрутить к опроснику перед источниками.
2. Убедитесь, что отображается форма, а не текст шорткода.
3. Пройдите шаги, добавьте историю проживания и несколько поездок.
4. Вернитесь назад: ответы должны сохраниться.
5. Отправьте анкету.
6. Должен появиться предварительный результат, после него — предложение с ценой товара EDD.
7. Нажмите «Перейти к оплате» и проверьте товар, цену и доступность Stripe на кассе.

Не оплачивайте тестовой картой на работающем сайте. На этом этапе можно проверить переход к кассе и остановиться.

## 8. Полная проверка оплаты на staging

Используйте отдельную тестовую копию сайта. Работающие настройки Stripe основного сайта не меняйте.

1. На staging настройте тестовый режим EDD и тестовое подключение Stripe по документации установленной версии.
2. Выберите товар и страницу анкеты в настройках плагина.
3. Пройдите анкету и покупку.
4. В тестовом режиме используйте карту `4242 4242 4242 4242`, будущую дату окончания и тестовый CVC.
5. Проверьте, что после подтверждения оплаты открывается инструкция.
6. Нажмите «Скачать PDF» и проверьте кириллицу, таблицы, переносы и ссылки.
7. Откройте ссылку из письма в другом браузере: она должна открывать только купленную инструкцию.
8. В браузере без ссылки/доступа полный результат должен быть закрыт.
9. Проверьте задержанную оплату, повторный щелчок, полный и частичный возврат, покупку с другим товаром, сбой PDF и повтор генерации.

Обязательна проверка реального тестового Stripe-вебхука. Ручное переключение заказа в «Оплачен» показывает реакцию плагина на статус, но не проверяет платёжную интеграцию Stripe.

## 9. PDF, кэш и письма

Для первого запуска оставьте хранение PDF в базе данных, как указано в README. Отдельный каталог или изменение wp-config.php для этого не нужны.

Проверьте, что сервер/CDN не кэширует `/wp-json/bgdvzh/` и скачивание через параметр `bgdvzh_download`. Персональные ответы должны возвращаться с `no-store`. Публичная статья и оболочка формы могут кэшироваться.

По README сторонние скрипты, загруженные раньше плагина, способны прочитать секретный фрагмент ссылки. Перед запуском исполнитель должен проверить страницу и исключить попадание токенов и персональных данных в аналитику, запись сессий и журналы.

Письмо со ссылкой уходит на email заказа по описанию плагина. Проверьте фактическую доставку и папку «Спам». SMTP нужен только при проблемах с уже действующей отправкой почты; новое подключение Stripe не требуется.

## 10. Если что-то не работает

| Признак | Что проверить |
|---|---|
| «Не выбран товар EDD» | Товар выбран и настройки сохранены |
| Товар отсутствует в списке | Товар создан в «Загрузки», сохранён/опубликован; обновите экран настроек |
| Видно сам шорткод | Плагин активен, шорткод точный, вставлен блоком «Шорткод» |
| Ссылка не прокручивает | `id="anketa-dvzh"` присутствует один раз и соответствует href |
| Цена неправильная | Цена и вариант выбранного товара EDD |
| Постоянно «нужна проверка» | Какие пояснения выданы; заполнен ли проверенный ориентир дохода; полнота ответов |
| После кнопки пустая корзина | Совместимость сессии EDD с REST; снимок и события анкеты; передать исполнителю |
| Оплата есть, инструкция не открылась | Реальный статус заказа EDD, привязка позиции к снимку, выбранная страница и события анкеты |
| PDF не создаётся | Состояние документа в «Анкеты», журнал ошибки, зависимости сборки и лимиты PHP |
| Письмо не пришло | Email заказа, спам, отправка писем WordPress/EDD |

При технической проблеме передавайте исполнителю текст ошибки и обезличенные сведения о заказе/анкете. Не публикуйте секретные ссылки, ключи Stripe или персональные ответы.
